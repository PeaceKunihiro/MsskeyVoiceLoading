# Misskey自動読み上げ Chromium拡張 実装依頼

## 目的

Chromium互換ブラウザ上で表示しているMisskeyのタイムラインを監視し、**中央タイムラインに新しくロードされたノート本文だけを自動読み上げソフトへ送信する拡張機能**を作成してください。

Misskey APIやStreaming APIは使用せず、**現在ブラウザ画面に実際にロードされたDOMを監視する方式**としてください。

Windowsデスクトップ環境での使用を前提とします。

---

## 想定環境

* Windows 11
* Chromium互換ブラウザ

  * Google Chrome
  * Microsoft Edge等
* Misskey Webクライアント
* 棒読みちゃん
* BouyomiChan WebSocket Plugin等、ブラウザから棒読みちゃんへ文章を送信できる既存手段

対象Misskeyインスタンスの実HTMLを参考資料として添付します。

---

# 基本動作

以下の流れで動作させてください。

1. Misskeyページを開く
2. 中央タイムラインのDOMを監視する
3. 新しいノートがDOMへ追加されたことを検出する
4. ノート本文だけを抽出する
5. 読み上げ不要な要素を除外する
6. 抽出した文章を棒読みちゃんへ送信する

Misskey APIからノートを取得する方式にはしないでください。

---

# DOM監視

`MutationObserver`を使用して、新規ノート追加を検出してください。

参考HTMLでは、通常ノートは概ね以下の構造です。

```html
<div data-scroll-anchor="NOTE_ID">
    <article>
        ...
        <div>
            <span class="_selectable" style="white-space: pre-wrap;">
                ノート本文
            </span>
        </div>
        ...
    </article>
</div>
```

`data-scroll-anchor`の値はノート固有IDとして利用できるため、可能なら重複判定にも利用してください。

ただし、

```text
xcSej
x48yH
xDn7E
```

などのMisskey内部class名は将来変更される可能性があります。

そのため、可能な限り以下を優先してください。

1. `data-*`属性
2. DOM階層
3. `article`
4. `_selectable`
5. class名

生成済みのランダム風class名への依存は最小限にしてください。

---

# 読み上げ対象

中央タイムラインへ新しく追加された**ノート本文のみ**読み上げてください。

例：

画面表示

```text
幸乃ととめ @amamamaou
ぶいちゃの接続が切れた
2分前
```

読み上げ内容

```text
ぶいちゃの接続が切れた
```

以下は読み上げません。

* 表示名
* @ユーザーID
* 投稿日時
* 公開範囲
* リアクション
* 返信ボタン
* Renoteボタン
* メニューボタン
* 添付画像名
* URLプレビュー
* 右側の通知欄
* 左側のメニュー

---

# 新規ノートのみ読み上げ

拡張機能起動時点ですでに存在するノートは読み上げないでください。

起動時：

```text
既存ノート
→ 既読扱い
```

起動後：

```text
新規DOM追加
→ 読み上げ
```

としてください。

---

# 重複読み上げ防止

Misskey側でDOM再描画が行われても、同一ノートを再度読み上げないようにしてください。

可能なら、

```text
data-scroll-anchor
```

の値をNote IDとして使用し、

```js
Set
```

などで既読IDを保持してください。

ページ再読み込み後の永続保存までは不要です。

---

# CW対応

CW付きノートは、**未展開状態では本文を読み上げない**仕様としてください。

参考HTMLではCW本文はDOM上には存在しますが、

```html
<div style="display: none;">
```

配下に格納されています。

そのため、単純に`textContent`を取得すると非表示CW本文を誤って読み上げる可能性があります。

本文候補要素について、実際に表示状態か確認してください。

例：

```js
element.offsetParent !== null
```

または同等の可視判定を使用してください。

CWタイトルについても初期版では読み上げ不要です。

---

# MFM対応

MFMの完全な構文解析は不要です。

DOMレンダリング後の本文から

```js
textContent
```

を取得し、可能な限りプレーンテキストとして読み上げてください。

例：

表示上

```text
愛をください
```

のようになっている場合は、その表示文字だけ読みます。

MFM装飾自体は読みません。

---

# カスタム絵文字

カスタム絵文字は読み上げないでください。

参考HTMLではカスタム絵文字は以下のような`img`要素へ変換されています。

```html
<img
    alt=":blobcat_dotadota_run:"
    title=":blobcat_dotadota_run:"
>
```

`textContent`取得時に自然に除外されるのであれば、それを利用してください。

`:emoji_name:`という文字列を読み上げる必要はありません。

---

# Unicode絵文字

通常のUnicode絵文字については、そのまま残して構いません。

読み上げソフト側でどのように処理されるかは初期版では考慮不要です。

---

# 画像のみノート

文章本文が存在しないノートは読み上げないでください。

例：

```text
カスタム絵文字のみ
画像のみ
ファイルのみ
```

の場合は無視してください。

---

# URL

本文中のURLは初期版ではそのまま取得して構いません。

ただしURLプレビューのタイトル、説明文、サイト名などは本文として読み上げないでください。

あくまで投稿本文に含まれているURLだけを対象としてください。

---

# 引用・Renote・返信

## 返信

返信ノートの場合でも、**新しく投稿された側の本文だけ**読み上げてください。

返信先ノート本文は読みません。

---

## 引用Renote

引用Renoteでは、可能なら**投稿者が追加した引用コメント部分だけ**読み上げてください。

内部に表示される引用元ノート本文は読み上げないでください。

---

## 通常Renote

本文を追加していない単純Renoteは、初期版では読み上げ不要です。

---

# 中央タイムライン限定

画面右側には通知ウィジェットがありますが、これは読み上げ対象外です。

中央タイムラインのノート一覧を特定し、その配下だけを監視してください。

ページ全体を対象に、

```js
document.body
```

以下のすべての`._selectable`を読み上げるような実装は避けてください。

---

# 棒読みちゃん連携

読み上げ先は棒読みちゃんを第一対象としてください。

既存のWebSocket Plugin等を利用し、

```text
Browser Extension
↓
WebSocket
↓
棒読みちゃん
```

の構成としてください。

可能であれば、接続先WebSocket URLを設定画面から変更できるようにしてください。

初期値例：

```text
ws://localhost:55000/
```

---

# 設定画面

最低限、以下を設定可能にしてください。

* 読み上げON/OFF
* WebSocket URL
* 読み上げ速度
* 音量
* ピッチ
* 声質ID

棒読みちゃん側の仕様に存在しない項目については無理に実装不要です。

---

# 動作確認用ログ

開発・デバッグ用としてConsoleへ最低限以下を出力してください。

```text
[MisskeyReader] initialized
[MisskeyReader] timeline detected
[MisskeyReader] new note: NOTE_ID
[MisskeyReader] speak: "本文"
[MisskeyReader] skipped CW
[MisskeyReader] skipped duplicate
[MisskeyReader] websocket connected
[MisskeyReader] websocket error
```

通常利用時に大量のDOM内容を出力する必要はありません。

---

# Chrome Extension仕様

Manifest V3で作成してください。

想定構成：

```text
MisskeyReader/
├─ manifest.json
├─ content.js
├─ background.js
├─ options.html
├─ options.js
└─ README.md
```

必要に応じてファイル分割は変更して構いません。

---

# セキュリティ

以下を守ってください。

* Misskeyのログイン情報を取得しない
* Cookieを読み取らない
* APIトークンを使用しない
* ノート内容を外部サーバへ送信しない
* 通信先はlocalhostの読み上げソフトのみ
* 不要なChrome権限を要求しない

---

# 初期対応サイト

まず以下のみ対応してください。

```text
https://misskey.niri.la/*
```

将来的に他Misskeyインスタンスへ対応しやすい構造にしてください。

---

# v0.1で不要な機能

以下は初期版では実装不要です。

* Misskey Streaming API
* MiAuth
* OAuth
* VOICEROID直接制御
* 複数音声エンジン切替
* ユーザー別音声
* ノート内容の高度なMFM解析
* URL読み上げ変換
* NGワード
* ユーザー別ミュート
* 読み上げ履歴保存
* 外部サーバ通信
* Chrome Web Store公開処理

---

# 最重要要件

以下を優先してください。

1. 中央タイムラインだけを監視する
2. 新規ノートだけを読む
3. 本文だけ読む
4. CWの非表示本文を読まない
5. 引用元や返信元を重複して読まない
6. 同一ノートを二重読み上げしない
7. カスタム絵文字を読み上げない
8. Misskey内部class名への依存を可能な限り減らす

---

# 実装時の進め方

いきなり全機能を作らず、まず以下を確認してください。

## Step 1

添付したMisskey保存HTMLを解析し、

* 中央タイムライン
* ノート単位
* Note ID
* 本文
* CW
* 引用
* Renote

をどのDOM構造から識別できるか確認する。

## Step 2

DOM監視とConsole出力だけ実装する。

新規ノート追加時に、

```text
NOTE_ID
本文
```

が正しく取得できることを確認する。

## Step 3

CW、引用、Renote等の誤検出を修正する。

## Step 4

棒読みちゃんWebSocket連携を追加する。

## Step 5

設定画面を追加する。

---

# 完了条件

以下を満たした時点でv0.1完成とします。

* Chrome/Edgeへデベロッパーモードで読み込める
* Misskeyを開くと自動で監視開始する
* 起動時既存ノートを読まない
* 新規ノート追加時だけ反応する
* 本文だけ取得する
* CW本文を勝手に読まない
* カスタム絵文字を読み飛ばす
* 画像のみノートは無視する
* 右側通知欄を読まない
* 同一ノートを二重読み上げしない
* 棒読みちゃんへ文章を送信できる
* WebSocket未接続時にMisskey本体の動作へ影響を与えない
