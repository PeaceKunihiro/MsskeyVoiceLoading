# Misskey Reader：棒読みちゃん依存撤去・VOICEVOX対応への変更依頼

## 目的

現在の `MsskeyVoiceLoading` は、棒読みちゃん + WebSocket Pluginを使用する設計になっています。

しかし、WebSocket Pluginが完成済みバイナリとして容易に導入できず、利用者側にビルド環境を要求するため、この方式を廃止します。

既存のMisskey DOM監視・本文抽出ロジックは維持し、音声出力部分のみ **VOICEVOX ENGINEのHTTP APIを利用する方式**へ変更してください。

対象リポジトリ：

```text
PeaceKunihiro/MsskeyVoiceLoading
```

---

# 変更後の基本構成

以下の構成としてください。

```text
Misskey Web
↓
content.js
↓
chrome.runtime.sendMessage()
↓
background.js
↓ HTTP
VOICEVOX ENGINE
http://127.0.0.1:50021
↓
WAV生成
↓
Chrome拡張側で音声再生
```

棒読みちゃん、WebSocket Plugin、独自Windowsブリッジアプリは使用しません。

---

# 最重要方針

既存の `content.js` に実装済みの以下の処理は、原則変更しないでください。

* Misskey DOM監視
* MutationObserver
* `data-scroll-anchor`による重複防止
* 既存ノートの初期既読化
* 新規ノート本文抽出
* CW除外
* カスタム絵文字除外
* 引用・返信元の除外
* 画像のみ投稿の無視
* 中央タイムライン判定

変更対象は主として以下です。

```text
background.js
options.html
options.js
manifest.json
README.md
```

必要がある場合のみ `content.js` を最小限変更してください。

```text
makeTalkCommand()

```

# VOICEVOX ENGINE接続

既定のVOICEVOX ENGINE URLを以下としてください。

```text
http://127.0.0.1:50021
```

設定画面から変更可能にしてください。

将来的にTailscale等を利用して別PCのVOICEVOX ENGINEへ接続できるよう、

```text
http://100.x.x.x:50021
```

のようなIPアドレスも設定可能な設計にしてください。

ただし初期値は必ずlocalhost相当とします。

---

# VOICEVOX API利用方法

VOICEVOX ENGINEの一般的なAPIフローに従ってください。

## Step 1：audio_query

読み上げ文章とspeaker/style IDを指定して、

```text
POST /audio_query
```

を呼び出します。

概念例：

```text
POST http://127.0.0.1:50021/audio_query
    ?text=こんにちは
    &speaker=3
```

返却されたJSONを取得してください。

---

## Step 2：必要に応じてパラメータ調整

`audio_query`のレスポンスJSONに対して、設定画面の値を反映してください。

初期対応項目：

```text
speedScale
pitchScale
intonationScale
volumeScale
```

VOICEVOX ENGINE側の正しい仕様・有効範囲を確認して実装してください。

棒読みちゃんの旧設定値をそのまま流用しないでください。

---

## Step 3：synthesis

調整済みaudio query JSONを、

```text
POST /synthesis?speaker=<styleId>
```

へ送信してください。

Content-TypeはVOICEVOX ENGINE仕様に従ってください。

返却されるWAVデータをBlob等として取得してください。

---

# 音声再生

取得したWAVをChrome拡張から再生してください。

Manifest V3のservice workerでは通常のDOM Audio APIを直接利用できない可能性があるため、現在のChrome Extension仕様を確認した上で適切な方法を選択してください。

候補としては、

```text
offscreen document
```

等を検討してください。

重要：

**service worker内で単純に `new Audio()` を使用できると決め打ちしないでください。**

Chrome Manifest V3でバックグラウンド音声を再生する正規の方法を確認して実装してください。

---

# 読み上げキュー

Misskeyでは短時間に複数ノートが追加されるため、音声を同時再生しないでください。

以下のようなFIFOキューを実装してください。

```text
Note A
Note B
Note C
↓
VOICEVOX生成
↓
A再生完了
↓
B再生
↓
C再生
```

1件ずつ順番に、

```text
音声生成
↓
再生
↓
再生完了
↓
次のノート
```

としてください。

音声が重なって再生される実装は禁止です。

---

# キューの実装場所

音声キューはMisskey DOM側ではなく、音声出力側で管理してください。

推奨：

```text
content.js
  ↓ speak message

background.js
  ↓ enqueue

speech queue
  ↓

VOICEVOX API
  ↓

audio playback
```

これにより、DOM監視ロジックと音声処理を分離してください。

---

# VOICEVOX話者取得

設定画面でspeaker/style IDを数字だけ手入力させる方式より、可能であればVOICEVOX ENGINEの

```text
GET /speakers
```

を利用してください。

VOICEVOX ENGINEへ接続できる場合、

```text
キャラクター
 └ スタイル
```

を取得して、設定画面で選択できるようにしてください。

例：

```text
四国めたん
 ├ ノーマル
 ├ あまあま
 └ ツンツン
```

内部的にはstyle IDを保存してください。

---

# VOICEVOX未起動時

VOICEVOX ENGINEが起動していない場合でも、MisskeyやChrome拡張をクラッシュさせないでください。

例えば、

```text
Failed to fetch
ECONNREFUSED
```

相当が発生した場合、

Console：

```text
[MisskeyReader] VOICEVOX connection error
```

設定画面：

```text
VOICEVOX ENGINEへ接続できません。
VOICEVOXが起動していることを確認してください。
```

と表示してください。

新規ノートの監視処理自体は継続してください。

# manifest.json変更

現在存在する、

```json
"host_permissions": [
  "ws://localhost/*",
  "ws://127.0.0.1/*"
]
```

を削除してください。

VOICEVOX用HTTP通信へ変更してください。

最低限：

```text
http://localhost:50021/*
http://127.0.0.1:50021/*
```

へのアクセスを許可してください。

ただし設定画面からTailscale IP等を指定可能にする場合、Manifest V3のhost_permissions制約を確認してください。

不要に

```text
http://*/*
```

のような広範な権限を要求することは避けてください。

必要なら `optional_host_permissions` の利用を検討してください。

# セキュリティ要件

VOICEVOX ENGINE URLについては、安全性を考慮してください。

デフォルトでは、

```text
localhost
127.0.0.1
```

を許可します。

Tailscale等で別PCを指定する機能を実装する場合も、

```text
http
https
```

以外のスキームを拒否してください。

外部の不特定WebサーバーへMisskey本文を送信する仕様にはしないでください。

---

# CORS

VOICEVOX ENGINEとChrome拡張間でCORSエラーが発生する可能性があるため、実際のVOICEVOX ENGINE仕様を確認してください。

もし拡張機能service workerからの `fetch()` でhost_permissionsにより問題なく通信可能なら、その方式を優先してください。

CORS回避のためだけに外部プロキシや自作Windows EXEを追加することは禁止します。

# 完了条件

以下をすべて満たしてください。

1. VOICEVOXを通常起動するだけで利用可能
2. 別途WebSocketプラグイン不要
3. 別途WindowsブリッジEXE不要
4. 利用者によるビルド作業不要
5. Misskeyの新規ノート本文をVOICEVOXで読み上げられる
6. 起動時既存ノートを読み上げない
7. CWを勝手に読み上げない
8. カスタム絵文字を読み上げない
9. 複数ノートが来ても音声が重ならない
10. 話者を設定できる
11. 読み上げ速度等を設定できる
12. VOICEVOX未起動時にもMisskey側へ影響しない
13. 「テスト読み上げ」で接続・生成・再生まで確認できる
